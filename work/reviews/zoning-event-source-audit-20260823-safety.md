## Scope and reasoning

The commit adds a read-only audit path:

- pure source classification in `acquisition/src/lib/zoning-event-source-audit.ts`;
- cohort orchestration in `acquisition/src/lib/zoning-event-source-audit-runner.ts`;
- an S3-reading CLI in `acquisition/src/zoning-event-source-audit-run.ts`;
- tests for classification, retracted exclusion, nested-key reads, and unknown read failures.

Safety-relevant behavior checked:

1. **Served contract / false retraction protection**
   - `observeZoningEventSources` requires collection-level `as_of`, `complete`, `muni`, event shape, unique `event_id`, and per-event `muni` equality.
   - It validates the served `state` against `active | corrected | retracted` and computes `is_living_phantom` only when `event.state !== "retracted" && source_state !== "has-source"`.
   - The runner catches missing/unreadable/corrupt documents and records the city as `audit_state: "unknown"`, with `counts: null` and no events, rather than folding it into `no_source`. This is the important fail-closed behavior for avoiding an audit result that could falsely authorize cleanup/retraction from absent evidence.

2. **Source classification**
   - Defaults are exactly `url_pdf` and `provenance.source_url` (`DEFAULT_ZONING_EVENT_SOURCE_FIELDS`).
   - The classifier is parameterized via `fields`, supports nested dot paths, rejects empty/duplicate/invalid paths, and does not silently consult defaults when custom fields are passed.
   - The state space is the pure audit triad `has-source | invalid-source | no-source`; no capture, mutation, or remediation state is introduced.

3. **Read-only S3 reachability / no served writes**
   - The CLI imports only `getBytes` and `s3Client` from `./lib/s3.js`; it does not import `putBytes`, `putBytesIfAbsent`, copy/delete helpers, or the zoning-events serving store.
   - The only S3 operation in the new CLI path is `getBytes(s3, key)` inside the `readDocument` callback.
   - Output writes are local report writes under `work/coverage/` only, guarded by `inside(COVERAGE, outputPath)`. There is no publish/apply flag and no code path writing `normalized/...` served objects.
   - The runner selects `zoningEventsKeys(slug)[1]`, i.e. the nested geo-api key (`normalized/ca-qc-zoning-events/qc-zoning-events-<slug>/qc-zoning-events-<slug>.geojson`), matching the requested nested-key cohort runner.

4. **Determinism**
   - Cohort slugs are sorted after parsing and again in `auditZoningEventSourceCohort`.
   - `mapConcurrent` writes results back by input index, so concurrency does not perturb city order.
   - Event rows are sorted by `event_id` before counting/output.
   - Report JSON is generated by stable insertion order from deterministic data structures.

- **Reasoning:** `acquisition/src/lib/s3.ts` itself defines write helpers and imports SDK write commands, so a module-level search will still see write-capable symbols in the dependency module. However, within the exact commit's new audit CLI and runner call graph, there is no reachable served write path or user-controlled switch that enables one. This satisfies the "absolutely no served writes" objective for this audit path.
