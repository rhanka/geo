## Change delivered

- `pv-refresh-plan.ts` lists authoritative S3 keys read-only, requires an
  explicit `--as-of`, produces deterministic selection/reporting, emits a full
  hashed inventory, and never changes the coverage matrix.
- Selection is capped at 10 targets, requires at least a 1,000 ms request
  floor, prioritises missing configured keys, and treats `LastModified` only as
  a revalidation scheduling threshold—not source freshness.
- `pv-index-run --refresh-before` enforces that same ten-city cap. It fails
  closed on all non-404 S3 reads; re-HEADs and reads an existing object before
  a write; and writes only a semantic change.
- Existing DOM/JS/specialized manifests are protected by
  `_refreshAdapter: pv-index-run/v1` provenance. A separate
  `--allow-legacy-generic` route is explicit, still capped at ten, and accepts
  only the exact historic generic `pv-index-run` note plus matching slug,
  source ID, and index URL. It is never the default.

No fleet configuration was changed and no API was restarted.
